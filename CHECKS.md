# Acceptance

Record pass, fail or not run with evidence.

- The question, intended user and success criteria are explicit.
- The target stack and existing behavior are observed or labeled unknown.
- Material technical claims have primary-source links and checked dates.
- Versions and licenses are checked at the relevant file or package scope.
- At least the current approach and a plausible alternative are compared.
- Reading depth and actual execution are distinguished.
- The recommendation explains tradeoffs and evidence that could overturn it.
- Proposed changes name exact paths, dependencies, checks and recovery.
- Open blockers and unsupported claims are visible.
